# Contributing to HRMS

Welcome to the team! This guide covers how to set up the project and work on it together.

## Repo

```
https://github.com/Shaik123Imran/hrms
```

All work happens on the `main` branch. Everyone works on the same repo (no forks needed).

## 1. First-time setup

**Prerequisites**

- **Git** — install from https://git-scm.com/download/win
- **Node.js 20+** — install from https://nodejs.org

**Clone the project**

```bash
git clone https://github.com/Shaik123Imran/hrms.git
cd hrms
npm install
```

**Set your Git identity (one time)**

```bash
git config --global user.name "Your Full Name"
git config --global user.email "you@example.com"
```

> Use the email tied to your GitHub account so your commits are attributed to you.

## 2. Run the app

```bash
npm run dev
```

Open **http://localhost:5173** in your browser.

Other useful commands:

```bash
npm run build    # production build (outputs to dist/)
npm run lint     # run the linter (fix warnings before pushing)
npm run preview  # preview the production build
```

## 3. Daily Git workflow

Always pull the latest before you start:

```bash
git pull
```

Then make your changes. When you're ready to share them:

```bash
git add .                    # stage all changes
git commit -m "Describe what you changed"
git push
```

**Commit message style**

Keep it short and descriptive, written in the imperative:

- ✅ `Add login page`
- ✅ `Fix leave date validation`
- ❌ `done`
- ❌ `changes`

## 4. Branching (recommended for bigger changes)

For anything more than a small fix, create your own branch so `main` stays stable:

```bash
git checkout -b feature/login-page
# ... make changes ...
git add .
git commit -m "Add login page"
git push -u origin feature/login-page
```

Then open a **Pull Request** on GitHub (`New pull request` → base `main` ← your branch) and ask someone to review it. Once merged, switch back and update:

```bash
git checkout main
git pull
git branch -d feature/login-page
```

## 5. If you get a merge conflict

A conflict happens when two people edit the same lines at the same time. When you see `CONFLICT` during `git pull`:

```bash
# 1. See which files conflict
git status

# 2. Open the conflicted files — look for:
#    <<<<<<< HEAD  (your version)
#    =======       (separator)
#    >>>>>>> origin/main  (their version)
#    Keep one side or merge both, delete the markers

# 3. After fixing all files:
git add .
git commit -m "Resolve merge conflict"
```

If you're unsure what to keep, ask — don't delete the other person's work.

## 6. Project notes

- **No backend (yet)** — the app uses mock data in `localStorage`. When a real API arrives, only files in `src/services/` change; the pages don't need to be touched.
- **`node_modules` and `dist` are ignored** — never commit them. `dist/` is generated by `npm run build`.
- **Run `npm run lint`** before pushing to keep warnings low.
- **Pull before you push** — if GitHub rejects your push, run `git pull --rebase` first, then `git push` again.

## 7. Adding a new teammate (repo owner)

On GitHub → repo → **Settings → Collaborators and teams** → add the person's GitHub username with **Write** access so they can push.
